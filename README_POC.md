# Sonic Chaos: Turquoise Hill Act 1 — Windows prototype 14

See [prototype 14 notes](POC_notes/README_14.md) for the current collision, ramp and spring changes and remaining test scope. Earlier sections below describe historical prototypes.

## Run
Extract into a NEW folder, open SonicChaos_POC.yyp in your working GameMaker LTS2026 installation, press F5, then Start Game / first stage. Use existing movement and jump controls. R restarts from the beginning; F2 switches to the original engine sample. Unpause before using these keys.

## Changes in prototype 04
- Chaos-specific climbing checks the actual next horizontal position before horizontal movement. Normal and rolling forms can step up sharp contours, while the existing sample-room handling stays as it was.
- Descending contours are followed after built-in movement in End Step, preventing the player from being pushed into the previous tile's solid ground.
- Three autogenerated wall strips that touched slope edges have been removed.
- These are prototype adaptations of GameMaker movement to Chaos geometry. A Windows gameplay test is needed to tune their step distances.

## Changes in prototype 03
- Four spring variants now select the jump sprite from the player instance, fixing the contact crash in 02.
- Original tilted tile 54 points right (+8) and tile 56 points left (-8). Their vertical speed is -18. The first upright spring is -30; the later upright spring remains -27.
- Loop rim colliders no longer block movement. If Sonic falls into either hollow loop, a temporary release moves him to the far side after 10 frames. This is a traversal aid and visibly skips the loop; 360-degree running still needs dedicated physics.

## Changes from prototype 01
- Full 4096 × 1024 Act 1 terrain layout, replacing the 1024-pixel opening slice.
- Correct background palette: the original loader's palette index 21. Prototype 01 incorrectly used the sprite palette, index 6.
- Terrain split into four 1024-pixel sprites to avoid a single oversized texture.
- Eight dedicated springs at extracted positions: vertical and diagonal launch, including rolling Sonic. The first upright spring uses -30 with normal gravity of 0.8, for an unobstructed theoretical rise of about 577 pixels. This is a prototype tuning value, not a recovered Chaos physics constant.
- Extracted ring placements, four ring monitors and four spike blocks.
- Bridge artwork has collision contours. Loop walls no longer stop Sonic, and a temporary release prevents getting trapped in a hollow loop. Full 360-degree loop-running is not implemented.
- Five existing-engine enemies at provisional test positions. These are not Chaos enemy graphics or original object placements.
- Automatic checkpoints after passing 1024, 2048 and 3072 pixels and settling on ground. A message confirms each save. Death can restart at that position; R deliberately clears it.
- Yellow FINISH marker at the right end. Crossing it records rings/time and stops the timer. R starts another run.
- Original engine sample rooms retained.

## First playthrough checklist
1. Check the corrected colours at the start.
2. Try the first vertical spring while standing and rolling; it should launch much higher.
3. Explore the upper and lower routes, especially the first curved slope, fast rolling on later hills, diagonal springs, loop exits and bridge.
4. Collect rings, break a monitor, jump on a sample enemy, and test spike damage.
5. Confirm a checkpoint message and respawn, then try reaching FINISH.

## Status and limitations
All registered resource paths, sprite-frame files and room instance references passed static checks. This version has not been compiled or played in GameMaker here. A complete start-to-finish playthrough still needs your Windows test. If stuck, send a screenshot of the location and describe whether Sonic is blocked, falls through, or misses a spring.

The original layout, graphics and basic collision-height records come from the supplied Sonic Chaos SMS disassembly ROM. Bridge masks are adapted from their decoded artwork; hollow loops use a temporary exit assist. Player controls, gravity, combat, HUD and character sprites remain Open Sonic SMS behaviour; they are not a faithful reconstruction of Chaos physics. Water/background art is static, without a completed original water system. No original enemy-placement decoder, animated scenery, original signpost scoring sequence or Vita build is included.

Checkpoints and the finish marker are prototype additions. This build aims to establish traversal of the full act before matching every original mechanic.

## Prototype 05
- Added the missing rightward horizontal spring at world (3200, 832), decoded from Chaos block 51 (collision type 0A). Lateral springs retain momentum for 18 frames. Horizontal springs keep Sonic on the ground; angled springs still launch upward.
- Full solid terrain masks now use rectangular collision. Press F3 to see Sonic's foot position and whether the engine detects solid floor at that point; a screenshot here will help isolate the remaining embedding issue.
- Comparing Chaos collision types with the Sonic 2 SMS disassembly found types 09 (vertical spring), 0A (horizontal), 14 (diagonal); Act 1 has no block of the Sonic 2 breakable type 0D. This does not rule out Chaos objects handled through a different system.
- The supplied ROM offset notes identify four loop motion/camera arrays at 34000–34A48. The additional SMS 1.2 music note gives a song start at $9169 and the FD 49 header marker. In the supplied ROM, bytes at $9169 are FD 49 and 17 such markers occur from $9000 to $BFFF. All 68 sound test IDs and offsets for both versions are recorded in POC_notes/sound_test_offsets.json; rendering audio still needs investigation; a bare song byte stream is not a playable audio file.
- This build needs a Windows GameMaker run. The existing loop exit assist remains temporary.

## Prototype 06
- Fixed the F3 debug Draw event compile failure: local `solid` conflicted with GameMaker’s built-in instance property. No other gameplay changes from 05.

## Prototype 07
- Raised platform tile 13 had a one-pixel collision line; a 24-pixel top band and a local one-way collision check now prevent falling through during normal movement. This is the section shown with Sonic inside the grass in the last screenshot.
- Moved two provisional test enemies to the actual upper ground surface. Test enemies still do not represent decoded original Chaos enemies.
- POC_notes/THZ1_object_records.json contains all 53 records from the separate THZ1 object placement table at ROM $705AE, with unverified type IDs left as raw values.
- Tiles 88–108 (flag $17) and 72–85 (flag $B0) contain zero vertical collision height in the ROM, and we do not silently assume they are solid. The single tile 175 (flag $4C) has solid height but needs its Chaos behavior identified. There is no Sonic 2 style breakable flag $8D in the Act 1 tiles. The precise breakable block mechanism remains unresolved.
- GameMaker runtime testing is still needed for the raised platform and spring behavior. F3 shows Sonic's collision foot and floor detection during gameplay.
