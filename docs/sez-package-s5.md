## Widescreen-only symmetric boss-edge adapter (POC gameplay adapter, NOT recovered ROM behaviour)

The S5B fixed X=2991 player wall was rejected (artificial, claustrophobic). Sonic now keeps the full live `EDGE(LEFT,+16)..EDGE(RIGHT,-9)` bounds at every width (the plain `chaos_goal_clamp_player`).
Instead, for views **wider than 256 px only**, the canonical right-edge boss relationships are mirrored onto the left so `$54` can use the whole arena:

* left stop: states 7/8 zero a **negative** X speed when the cached screen X is `<= EDGE(LEFT,+44)` (canonical right stop: nonnegative speed at `>= EDGE(RIGHT,-44)`);
* left escape: the state-10 selector requests state 11 when boss screen X `<= EDGE(LEFT,+48)` and the cached player screen X `<=` the boss' (canonical: `>= EDGE(RIGHT,-48)` and player `>=` boss);
* direction: the ROM direction rule (`bossX - playerX < 96` → right) keeps the boss hovering ~96 px right of a Sonic hiding at the left, so the mirrored stop/escape alone were unreachable. In a wide view a Sonic whose cached screen X is `<= 48` keeps the bounce direction left. Speeds, Y thresholds, HP/contact, scripts, `$55`, the 160/304 trigger are untouched;
* both escapes feed the existing state 11 → 12 chain; state 12 copies the player X, so the slam lands on Sonic at either edge. At exactly 256 px nothing is added: Research behaviour is byte-for-byte (tested for every cached byte pair).

Research `53e9095` also confirms the canonical right-edge escape and that the 256 left edge is not universally safe (`$55` reaches it). The renderer skips cache preparation for asleep (flags4 bit 6) objects (stale boss cache while asleep).

## Explosion may be skipped depending on final-hit phase (documented canonical behaviour, no correction)

Replaying the shipped logic with HP 1: a final hit in state 7 early/mid rise, state 8 (Y < 610) or state 10 gives request 4 after `$A3D8`, 4 at callback end → state 4, five puffs. A final hit **at the state-7 apex** (updated Y speed >= 0, e.g. Y 514, vy 0 → +24) gives request 4 after `$A3D8` but **5** at callback end
(the callback's `INC`), so state 4 is never entered, no puffs, and state 5 clears directly; states 8/9 at Y >= 610 do the same, and state 10 at Y >= 622 is overwritten by 7/11 (the `$A3D8` re-request then reaches 4 on the next callback). These are exactly the Research-approved final-hit overwrite cases (144 boundary rows verified).

## Suggested Windows pass

1. Walk right into SEZ3: the HUD slides away as the boss object appears (earlier than at 256 px by half the extra width), the camera locks (wide view: more arena to the left), the boss drops and combat starts.
2. Hit it from above **without spinning** (plain jump/walk-into) — HP still drops; spin attack only changes the rebound. Eight hits (18-update cadence) defeat it.
3. Watch for 3-child volleys from the rising state, the right-stop (no left stop), the escape flight above the screen and the drop onto Sonic.
4. Defeat: five puffs, bonus sparkles; land (floor required) → state `$20` run → MGHZ1.
