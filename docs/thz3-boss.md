# THZ3 boss, arena, and clear adapter

Source: Research `main` at `d502e34`, especially `data/rom-cache/thz3/implementation-manifest.json` and `data/rom-cache/thz3-boss-support.json`. The POC mirrors both files byte for byte in `POC_notes/rom-cache/`. `POC_notes/generate_thz3_boss_data.js` emits the numeric GML constants and puff fixtures; `verification/verify_thz3_boss.js` checks the mirror and generator.

The canonical type `$50` placement is loaded from the existing THZ3 object row at world `(1936, 238)`. Its state model uses the 19 Research states. The internal `-1` value means the placement awaits the right-edge creation band; `-2` is the GameMaker camera controller after the ROM slot has converted to type `$0F`. These values are adapters and are not ROM states. The converted slot is marked `$0F` for 38 updates, then `$FF`; a separate type `$0F` visual instance renders the poof. This retained hidden controller lets the released camera continue following Sonic without moving the canonical boss anchor.

The arena camera has its own mode. Creation uses `EDGE(RIGHT,+32..+95)`, activation uses strict `PLAYER_DIST(160,256)`, and the pan moves one pixel per update to `LOCKED_CAMERA(1679,78)`. At the original 256px width, the arena clamp is the canonical world interval `1695..1926` and the patrol thresholds remain `1735..1879`. Boss contact reads canonical player and boss anchors through `$6328` geometry, projects along the contact axis, and tests attack bit 1. It does not read the GameMaker sprite mask, jump flag, or invincibility as attack permission. The accepted shared state `$20` tail handles the clear flag; boss conversion uses it directly without the `$18` sign trigger.

**GameMaker widescreen boss-arena adapter:** `extra = max(0, viewport_width - 256)`. The left arena and patrol limits stay canonical; the right arena limit is `1926 + extra`. At 256px, the right patrol threshold remains the canonical `1879`. At wider views, it is `max(1879 + extra, arena_right - 28)`, using the canonical boss contact reach for edge coverage. At 640px, the arena is `1695..2310` and the right patrol threshold is `2282`; a player at the right clamp is exactly 28px from a boss at that threshold. This is a GameMaker adapter, not ROM behavior. Boss speed, contact geometry, phase timing, camera target, terrain, and Research cache are unchanged. The extended patrol is intentionally not speed compensated.

Type `$12` is a HUD presentation adapter: the three existing HUD rows slide up at half a pixel per update. Its 98-update completion gates the arena pan. Type `$34` uses five ROM-derived puff sprites at the recovered offsets and lifetimes. Type `$0A` parameter 0 computes the packed `$D2A6` bonus once at conversion and persists as a controller that emits parameter `$FF` sparkles every eight updates. Type `$0F` uses the ROM-derived 38-update poof frames. Boss, mirrored boss, puff, sparkle and poof PNGs come from Research's `tools/thz3_boss_support.py --png` exporter; `POC_notes/install_thz3_boss_assets.py` installs them reproducibly.

Windows presentation repair: the original adapter rendered state 18 but set `visible=false` as soon as the boss entered state 6. The focused trace reproduces this at update 165 from its documented creation setup (`verification/thz3-boss-render-trace.json`). The replacement selector is generated from the byte-verified 19-state script records in the mirrored `object-50.json`; it uses normal frames 1-6, mirrored frames 1-4, and preserves the state-4 saved-frame/blank flicker. States 0-3 and 5 deliberately select blank mapping 0. The sprite canvas is 40x48 with GameMaker origin (20,48); ROM mapping bounds are X -20..19 and Y -48..-1 before the shared +18 screen registration. The instance's draw Y is now gameplay anchor Y+18, so the mapping envelope is anchor-30..anchor+17. The canonical gameplay anchor and contact box remain unchanged.

Windows clear repair: the shared state-`$20` beyond-map adapter still opened terrain only from X 4096. THZ3's 80-cell map ends at X 2560, so the state-`$20` side probe wrapped into a solid next-row tile at update 322 in the focused trace; Sonic was projected to X 2551 and stopped before `EDGE(RIGHT,+33)`. The adapter now uses the active map width for the empty beyond-map lookup and Y hold. The unchanged camera limit and clear edge then yield X 2595 at the flag in both 256 and 640 px verifier views. `verification/thz3-boss-clear-trace.json` records every update from the final hit through the POC's shared completion overlay and progression save. The original next zone (zone 1 act 0) has no POC room, so no playable room transition is available; this is the existing content boundary, not a boss-clear flag stall.

The latest handoff trace records the request frame and first `$20` update with player velocity, floor/attack flags, GameMaker sprite/frame, draw position, and camera. The fixture now carries the prior floor-tile flags when placing Sonic at `(1800,238)`; omitting them had produced a synthetic one-update Y dip. A real presentation mismatch remained when a grounded attack/roll bit survived the request: the generic sprite selector could keep drawing Sonic's spin frame during the automatic run. State `$20` now explicitly selects stop/walk/run artwork by its own horizontal speed while leaving the attack bit, terrain projection, movement, and request timing intact. The focused trace asserts the first `$20` sprite both with and without that bit.

Research's per-hit palette command 7 writes sprite palette colours 13 and 14 to `$3F/$3F` for four updates, then returns to `$35/$20`. The installer derives normal and mirrored flash frames from the ROM PNG export by applying only those palette changes. The boss selects those frames while its recovered four-update flash counter is active. A separate entry-frame correction leaves the state-3-to-18 request update blank; state 18's first mapping becomes drawable on its first update, as in the Research scripts.

The THZ3 timer continues during the fight and after the clear flag. `global.chaosFinishTime` samples it at boss conversion for the `$0A` bonus; `global.chaosBossClearScore` records the canonical `rings*10 + bonus steps + 500` total. The current POC's shared clear overlay and progression request remain the results tail. Results-screen graphics, audio playback for the recovered numeric requests, score-loop presentation, and the next zone's playable content remain deferred. The cleared THZ3 card is currently the last implemented act, so the saved act index is clamped there by the shared act table.
