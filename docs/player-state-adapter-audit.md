# Player state adapter audit — spring / airborne

Audit only, 2026-10-09. POC branch `poc/aqz-p1-foundation-water`; HEAD/accepted base `5d99a38d1f439ac02cd9d3010d09f70cc57aa575`. Research main inspected at `eb4bf953dcb2f1ad57c629543b55c8536eb688cb`. The new Research closure is pending Manager review. No behavior correction, animation import, commit, P2 work or replacement test package is included.

## Findings first

The presentation defect is established: `SCR_chaos_core_sprites` selects inherited Sonic sprites through attack/air flags and a sticky `chaosSpringVisual` latch. It does not select the audited states' recovered animation frames/program using `$D448`. A non-attacking ascending `$0B` uses the one-frame `SPR_sonic_jump`, frozen at index 0; subsequent airborne presentation usually uses the two-frame `SPR_sonic_falling`. The weak spring and THZ3 top bounce reproduce that same shared path in native GameMaker.

There is also a concrete state-request overwrite inside the current core: a horizontal spring requesting `$09` while current state is already `$09` is not protected by the `next != state` return. Opposing held input runs the rolling/braking suffix, requests `$07` and clears attack on the launch update. A matched `$0E` approach protects `$09` for that update, then the same held input brakes on the following update. Native traces establish this behavior; whether/how it differs from the ROM requires Research's state-handler and animation-scheduler closure. No collision enlargement or priority fix was applied.

The broad inherited player Step/End Step movement code does **not** run in Chaos rooms: both character classes exit through the Chaos adapter on their first line. The observed attack loss is a core write, not evidence that merely showing `SPR_player_falling` invokes Sonic 2 physics. The missing animation and gameplay symptoms must be reconciled separately, then implemented through one shared boundary.

## State translation matrix

All six states retain `OBJ_player_char` (or the already-existing spin class); adopting these states does not call `instance_change`. Ordinary collision remains in `SCR_cc_shared` and its fixed terrain probes; contact handlers read core flags. This table describes ordinary Sonic with the usual flag combinations, outside footwear/hurt/clear/route overrides. `state-adapter-matrix.json` also exercises all four air/attack combinations for each state and both `$D448` values.

| Chaos state | Current sprite selection | Legacy output | Core suffix / collision consequence |
|---|---|---|---|
| `$09` | Spin when `next==$09` or attack bit set | Jump true even when only attack is set; Spring false | Shared terrain pass. Opposing input with air clear requests brake and clears attack; leaving unsupported floor can request `$0A`. |
| `$0A` | Spin while attack is retained; otherwise generic air fallback | Jump from `(move&3)`; Spring false | Variable-jump handler, shared terrain. `SCR_cc_fall` explicitly refuses to replace current `$0A`; floor suffix walks. |
| `$0B` | Frozen inherited jump while spring latch and negative Y speed; falling otherwise | Jump from air/attack; Spring true only while requested state is `$0B`/`$1C` | State-specific gravity; grounded suffix walks, nonnegative Y speed requests `$0E`. `$D448` does not choose presentation. |
| `$0E` | Spin if attack remains set, otherwise falling while air is set | Jump from air/attack; normally Spring false | Ordinary shared terrain and ground-to-walk suffix. The fall setter additionally resets Y speed, clears attack and strip state. |
| `$1B` | Spin with attack; inherited jump only if a prior spring latch remains and rising; falling for non-attacking air | Jump from air/attack; Spring false | Different gravity from `$0B`; ground can clear air. No generic apex-to-fall suffix. |
| `$1C` | Spin when attack is set, otherwise latch/air fallback | Jump from air/attack; Spring true while requested `$1C` | Shared terrain; grounded suffix walks, nonnegative Y speed requests `$0E` and clears attack. |

`global.playerJump = (move&3)!=0` merges airborne and attack/rolling. `global.playerJumpSpring` follows **requested** state, while other outputs mix current and requested state. `global.playerSpinDash` follows requested `$0F`; Fly is forced false. Rocket suppresses both Jump mirrors. `chaosAttack` / `global.chaosAttackPosture` mirror bit 1 directly. Neither legacy Jump flag is the canonical attack authority.

## Adapter boundary inventory and leakage

The full text-reference inventory is `legacy-reference-inventory.txt`. Reachability classification matters: dormant inherited code is not an explanation for the traced core writes.

1. **Attach / external coordinates — `SCR_chaos_adapter`, attach and Step.** Initial GameMaker position/velocity seeds the core; later any instance position differing from the last publication is imported back, with no explicit provenance token distinguishing carry/debug placement from foreign legacy movement. Sprite-origin/anchor offset is derived from `SPR_player_mask`. This is a bidirectional engine boundary.
2. **Publication — `SCR_chaos_core_publish`.** Core positions, plane, terrain metadata, grounded status and attack are exported. Built-in hspeed/vspeed/gravity are zeroed. Jump merges two canonical bits; Spring uses requested state. The visual latch is set by `$0B` and survives until grounding/hurt/reset, rather than following a canonical animation state.
3. **Presentation — `SCR_chaos_core_sprites`.** `SCR_player_sprites` aliases retained Sonic/Tails/Knuckles/Super assets. Ordinary facing follows velocity and writes the GameMaker scale back into core `player_flags` bit 4; footwear instead follows the core facing bit. Visual state selection mixes current state, next state, movement bits and historical latch. Generic image speed follows horizontal velocity, not an animation-program counter. The latch can freeze an attacking **spin** sprite as well as jump. Sprite changes reset image index. None of the six audited states has explicit recovered frame playback.
4. **Shadow animation — `SCR_cc_anim_update`.** This is a terrain-ring parity model, not the visible animation engine. It passes literal zero for `$D448`, tracks durations but no visible frame IDs, and animation request opcodes update only the interpreter's local request value. It cannot serve as the completed Chaos animation/state scheduler. Its accepted ring-parity scope must be preserved until the new contract resolves scheduling.
5. **Mapped `$26` launch — `SCR_chaos_spring`.** The gameplay setter writes core next/velocity/flags and `$D448`. A separate presentation helper immediately forces inherited jump/index0/speed0 and releases support. The ordinary mapped Step event can run before the player callback; the host initially modeled it after the player. Native logs preserve actual event order. Publication can temporarily lag a setter; logs should distinguish setter values from subsequent mirror refreshes.
6. **Loop motion — `SCR_chaos_motion` and adapter End.** Legacy loop motion runs outside the ordinary core updater using published instance velocity/position. It selects run/spin from **GameMaker object class**, sets Jump true/Spring false, and on release imports position/velocity while forcing `move=1,next=$0E`. This can discard attack independently of animation. Loop entry also uses the GameMaker bbox bottom. Existing loop adapters are outside this audit's authorized repair scope.
7. **Sample rebound round trip — `SCR_physics_jump_objects`, type `$27` Destroy, adapter queued bounce.** The canonical bee defeat path can call the retained destroy/rebound helper, which queues a sample bounce. The next player pass sets scaled Y rebound, `$0A`, attack/air and jump counter. This is a real retained-sample-to-core gameplay path, outside AQZ's placement set; it must not be described as harmless sprite output.
8. **Type `$21` bounce / boss contact.** The stomp helper sets a spring visual latch and legacy Spring flag. THZ3 top contact requests `$0B` with attack clear; its runtime republishes the core but does not select the new sprite at that contact point. Both helpers leave `$D448` unchanged; `SCR_cc_new` does not initialize that member. An undefined or retained value is currently masked by the renderer ignoring it. Do not invent a new `$D448` write before Research specifies it.
9. **Mask consumers.** Player objects have no fixed `mask_index`; selecting spin/jump/falling changes the active GameMaker mask. Those assets share bottom33/origin20 but have different top bounds (spin13, jump3, falling8). Core probes and recovered numeric object contacts do not inherit those bounds. Legacy `place_meeting` monitor/sample-hazard checks and loop bbox entry still consume GameMaker geometry. Presentation therefore is not globally guaranteed collision-neutral at the engine boundary.
10. **Legacy collision / movement helpers.** Character Step and End Step early-exit in Chaos rooms, so inherited fall, spring gravity, landing, rolling object changes and Sonic 2 air handling below those exits are bypassed. Begin Step still selects aliases. Legacy spring collision handlers, `SCR_badnik_death` and `SCR_monitor_collisions` still interpret Jump/spin-class semantics if foreign legacy objects invoke them; generated canonical AQZ spring/monitor/enemy paths do not use those helpers. Create/reset paths initialize globals; alarm/character/debug controls remain engine infrastructure. No audited-state entry itself changes GameMaker object class.
11. **Breakable adapter scope.** Core surface `$0D`/`$10` floor/side tests use core attack, state and speed gates, not legacy Jump or spin class. Surface `$0D` underside breaking is a separate owner-clear branch with **no attack-bit test**; the successful corridor breaks through this branch. Do not impose an attack gate there from the preliminary scenario wording. The retained `SCR_chaos_block47_step` uses canonical attack gates but hard-coded THZ1 coordinates/cell indices and excludes GPZ/MGHZ/SEZ, not AQZ. This is a latent zone-scope boundary to reconcile, not the cause of the captured AQZ3 failure (its fixed world X range lies beyond AQZ3).

Canonical monitor/enemy/boss attack decisions examined use `$D503` equivalent bit 1 (or recovered ordinary-contact invincibility exceptions), not `global.playerJump`. Attack loss changes their results through actual core flags. Static-spike selector-6 behavior remains untouched.

## Update ordering and overwritten requests

`SCR_cc_tick` adopts `state=next`, then ordinary shared execution is: water updater where applicable, input, X/Y movement, floor projection/dispatch, right/left side projection/dispatch, ceiling dispatch, terrain probe, contact merge, pressed jump. The wrapper's suffix runs only when `next==state` afterward.

Floor fall can therefore precede a horizontal side spring. A later side/ceiling spring can replace a prior request. Pressed jump runs after springs; horizontal launch clears air, so the jump setter can replace its `$09` request. Diagonal terrain dispatch can also write X velocity, facing and `$D448` after the floor gate but before rejecting negative Y speed; a changed spring-call record is therefore not automatically a new launch. The guard protects a request with a **different numeric state**, not a newly requested instance of the same state. These are current POC semantics for Research to compare, not proposed new priority rules.

`SCR_cc_fall` is not merely a semantic name: except for current `$0A`, it requests `$0E`, sets Y speed +1, sets air, clears attack/floor and resets strip state. The `$0B/$1C` suffix calls it for nonnegative Y speed, including Y speed changed by ceiling collision. The sprite adapter then picks falling from the resulting flags; it does not call extra inherited fall physics because of the name `$0E`.

## Recommendation for Manager / Research reconciliation

Keep authoritative movement state, requested state, animation program/counter/frame, air bit, attack bit and `$D448` separate. After the ROM closure is accepted, supply an explicit Chaos presentation adapter driven by those fields; write legacy globals and GameMaker sprite/index as terminal outputs. Resolve state-wrapper/animation-program ordering from Research before choosing request priority or replacing apex/ceiling transitions. Preserve the terrain-ring parity contract while adding complete animation scheduling. Give external placement/carry, loop ownership/release and sample contact responses explicit boundaries so engine helpers cannot silently round-trip approximate state. Specify initialization/retention of `$D448` from evidence. Do not make airborne or a spring sprite imply attack.

Research comparison targets are the update44/45 ceiling-boundary pair, same-state horizontal request versus suffix, `$0B/$1C` nonnegative-Y transitions, weak ceiling interruption, and `$D448` retention after boss/type21 bounce. Existing traces are current-implementation regression evidence, not ROM approval. No geometry fix, forgiveness, attack-duration change or asset substitution is recommended before that comparison.
