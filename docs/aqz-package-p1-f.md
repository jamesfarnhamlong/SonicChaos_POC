## Root cause and measured scope

E selected Draw compensation from `visual_anim.active/state` and removed the
five-pixel engine anchor offset. Exact ROM canvases have mapping-space origins;
they also require the shared original renderer's terrain-space registration.
E therefore drew these frames at core Y instead of core Y+18, producing an
18-pixel lift. X likewise lacked the shared renderer's +1 relationship.
The state predicate could also apply compensation to retained art during a
state/resource mismatch. Origins themselves were not duplicated or corrupted.

Compiled D/E/F fixed-anchor controls record 191 actual Draw calls per package
(573 total), covering roll, spin charge, release, Rocket, fall, weak tumble,
idle separator and strong $61. Every control has core (400,400), instance
(400,405), chaosAnchorOffset=5. This establishes A: presentation shifts while
the published anchor remains fixed, for these controlled poses. These are
synthetic registration controls, not claims of a physical traversal replay.
The separate native AQZ3 replay supplies movement evidence.

Mid-phase Draw Y: D=405 throughout; E roll/release/fall/weak/strong=400,
charge/Rocket/idle=405; F ROM resources=418, retained charge/idle=405.
Thus charge-to-release introduces E's lift. Steady Rocket Draw was identical
in D/E; the reported broader Rocket symptom is not independently demonstrated
as an E-only steady-state change. F correctly registers its existing ROM frame
resource by the same shared rule, including transitions from/to exact frames.

D's legacy bbox varies by pose/object state. E/F use the same fixed
SPR_player_mask bbox (396,388)-(407,419). The mask does not set visible Draw
registration; canonical core probes/contact remain authoritative.

## Bounded adapter correction

`chaos_player_rom_resource` is generated by the existing approved-frame importer.
It identifies the 36 imported normal/indexed resources and the two existing
Rocket normal/indexed resources. `chaos_player_draw_registration` reads the
actual selected resource, independently of executing/requested state:

- ROM resources: floor(core X)+1, floor(signed core Y)+18.
- Retained artwork: existing GameMaker instance X/Y.

Research `mapped-object-registration.json` shared_renderer establishes this:
R8 background relationship +1; R9 relationship +17 plus SAT Y's +1.
The controlled RenderOracle uses player slot D500 and validates 42 original
renderer cases (18 approved frames plus 3 Rocket frames, both facings).
All canvas rectangles match original SAT bounds at that registration.
GameMaker applies the unchanged recovered origins once. No PNG, origin,
physics, player coordinate, spring launch or collision adjustment is made by F.
E scheduler, same-state requests, ceiling-spring dispatch and ring shadow parity
remain intact. Sprite identity also covers stale animation/fallback disagreement.

## THZ3 classification

stationary/falling velocities. Non-rising canonical top contacts request B,
write D448=0, launch -4 and clear attack; native boss255 follows the weak tumble
contract. Side/below request 1B. Rising top does not invoke the bounce.

A top contact while strong B is already executing retains its current frame61
record until the script loops and re-reads D448. This is the accepted same-state
scheduler contract, not a boss exception. No boss animation workaround added.
James's single historical missed occurrence has no associated contact trace;
its exact classification remains unresolved. F7 now logs classification,
resulting top request/D448, executing state and frame at subsequent Draw.

## Submerged gate

GML. Existing A2 crossing/physics fixtures remain required. Negative -769
(-3.00390625) has signed high byte -4 and qualifies, whereas +1023
(+3.99609375) has high byte +3 and fails. Nonnegative Y and D503 bit1 are required.
The repeated gate remains active on every submerged updater call.

A 30-update continuously submerged executing-core trace shows exactly one
updater per player update, before X/Y movement, and exact gate results.
Existing integration checks retain frozen loop/route, charge, recovery, clear
and death paths. Fall entry, upright spring and Rocket setters clear attack;
ordinary airborne jump retains it canonically. No ROM/POC gate or cadence
difference was found in these controls; no sensitivity tuning was performed.
